# CLAUDE.md

Git mirror of the FreeFileSync source code (C++26, wxWidgets/GTK 3), rebuilt from the official source zips at https://freefilesync.org/archive.php (past releases) and https://freefilesync.org/download.php (current release). `README.md` describes the app; `FAQ.md` and `MANUAL.md` summarize the official FAQ and manual (images in `docs/images/`, copied from freefilesync.org); `CONTRIBUTING.md` covers branches, importing releases, the source layout and building.

## Repository rules

- Release commits (`FreeFileSync <ver>`, authored by `Zenju <zenju@freefilesync.org>`, dated to the release) are exact snapshots of the upstream zips. Never amend, rebase, reword or squash them, and never commit local changes under Zenju's name.
- `upstream` holds release commits and the `.claude/` tooling only. Don't commit fixes, docs or experiments there; do that on `main` or a feature branch. These docs and `docs/` live only on `main`.
- New releases come in through the `ffs-upstream-update` skill (`.claude/skills/ffs-upstream-update/`), which commits to `upstream`, pushes it, and publishes a GitHub release per version (tag `v<ver>` on the release commit, commit subject/body as title/notes, the website's prebuilt downloads attached, never the source zip, which is the commit itself). Tags `v<ver>` must always point at the matching release commit. Never force-push `upstream` or move release tags. Merge `upstream` into `main` only when the user asks.
- `.github/workflows/ffs-upstream-update.yml` (on `main`, since scheduled workflows run from the default branch) runs the same scripts monthly from GitHub Actions. Keep it in step with the skill when changing the scripts' options or steps.
- The importer deletes everything in the working tree except `.git/` and `.claude/` before unpacking a release, so keep anything that must survive imports inside `.claude/` on `upstream`.
- `zen/`, `wx+/`, `zenXml/`, `libcurl/`, `libssh2/` and `xBRZ/` are part of the upstream snapshot, not vendored copies to update separately.

## Code structure

- `FreeFileSync/Source/`: app entry point (`application.cpp`), global config (`config.*`), paths, logging, localization (`localization.*`, `parse_lng.h`, `parse_plural.h`), status handling. `version/version.h` holds `ffsVersion`.
- `FreeFileSync/Source/base/`: the engine, free of UI code. `comparison.*` compares folders, `algorithm.*` and `synchronization.*` decide and run sync operations, `file_hierarchy.*` is the in-memory folder tree model, `db_file.*` stores the last-sync database for two-way sync, `path_filter.*`/`soft_filter.h` are include/exclude filters, `versioning.*` handles deletion versioning, `parallel_scan.*` scans folders in parallel.
- `FreeFileSync/Source/afs/`: `AbstractFileSystem` (`abstract.h`) with the `native`, `ftp`, `sftp`, `gdrive` and read-only `zip` (`zip:<archive>[|<folder>]`) implementations. Engine code reaches files through `AbstractPath`/`AFS`, never through OS APIs directly. File icons: `base/icon_loader.cpp` (GTK, Linux) and `base/icon_loader_mac.cpp` on top of `base/icon_loader_mac.mm` (NSWorkspace/ImageIO, compiled as C++23: the macOS 26 SDK's CoreGraphics headers are no valid C++26, so files that include AppKit stay behind a header with standard types only); `wx+/image_holder.h`'s `FileIconHolder` holds a GIcon on Linux and a rendered image on macOS.
- The engine library: everything except `application.cpp`, `ui/`, `wx+/`, `xBRZ/` and the crash reporting implementation, built by `make engine` as `libffs_engine.a` from the app's objects. It still compiles against wx headers in `config.*`, `localization.*`, `icon_buffer.*`, `base_tools.cpp`, `afs/native.cpp` and the icon loader (inventory in `CONTRIBUTING.md`, removed in M5).
- `FreeFileSync/Source/ui/`: wxWidgets GUI. `main_dlg.*` is the main window, `file_grid.*`/`tree_grid.*` the comparison views, `sync_cfg.*` the sync settings dialog, `batch_*` the batch jobs.
- `FreeFileSync/Source/RealTimeSync/`: separate app that watches folders (`monitor.*`) and launches a command; it has its own Makefile.
- `zen/`: platform layer and utilities in namespace `zen` (file access and I/O, `Zstring`, `FileError`/`SysError`, threads, HTTP, OpenSSL, zlib). `wx+/`: wxWidgets helpers (custom `Grid`, graphs, dark mode, popups). `zenXml/`: header-only XML serialization for config files.
- Generated code: `ui/gui_generated.*`, `RealTimeSync/gui_generated.*` and `wx+/popup_dlg_generated.*` come from wxFormBuilder, but the `.fbp` projects are not in the source zip. Edit them by hand only when unavoidable, keeping `.h` and `.cpp` in sync.

## Conventions in the upstream code

- App code is in namespace `fff`, the library in `zen`. Files start with the GPL header block and use `#pragma once`.
- 4-space indentation, no tabs, Allman braces, `//` comments, camelCase functions and variables, PascalCase types.
- Errors are reported by throwing `zen::FileError` (user-facing, with context) or `zen::SysError` (low level). Functions that throw note it in a trailing comment, e.g. `void f(); //throw FileError`. Follow that convention in any change.
- Strings shown to users go through `_("...")`/`_P(...)` from `zen/i18n.h` (force-included by the Makefile).

## Building and checking

- Linux only from these sources: `make -C FreeFileSync/Source -j"$(nproc)"` (and `make -C FreeFileSync/Source/RealTimeSync`). It needs g++ 14+ or clang 20+ (`-std=c++26`; the makefiles detect the compiler from its predefined macros, `$(CXX) -dM -E`, and add the GCC or clang warning flags only for a positively detected compiler) plus wxWidgets 3.3 built from source with `--disable-exceptions` (GTK 3), libssh2 built from a development commit (the `Bugs.txt` header change is optional: `afs/sftp.cpp` falls back to the same values), and the OpenSSL, libcurl, libidn2 and zlib dev packages. With glib 2.78+ it also needs the glib API capped at 2.76 through `CXXFLAGS`. See `CONTRIBUTING.md` for packages and steps; without a Linux toolchain (e.g. on macOS), build in the root `Dockerfile`'s image as described there. `make -C FreeFileSync/Source BUILD=debug` makes a debug build. `STDLIB=libc++` (with `CXX=clang++-20` in the environment) builds against LLVM's libc++, the C++ library of the macOS and Windows ports; wxWidgets must then be built with libc++ too. A toolchain other than g++ with libstdc++ gets suffixed binary and object folder names (`FreeFileSync_x86_64-clang-libc++`, `Build/Obj/FreeFileSync_x86_64-clang-libc++`); `toolchain_suffix` in `.github/build/common.sh` derives the same suffix for `build-free-file-sync.sh` and `package.sh`. Keep the sources compiling with both g++/libstdc++ and clang/libc++ (CI: the `clang + libc++` job in `linux-build.yml` and the second matrix entry of both test workflows); for a missing library feature prefer a fallback in `zen/legacy_compiler.h` keyed on `__cpp_lib_*` macros, and include what you use instead of relying on libstdc++'s transitive includes. There are no Windows/macOS project files. Both makefiles include `FreeFileSync/Source/platform.mk`: `TARGET_OS=linux|mac` (default from `uname -s`) and, on macOS, `ARCH=arm64|x86_64`, the deployment target from `common.sh` and the static libraries in `FFS_DEPS_PREFIX` (default `.build/deps/macos-<arch>`); the Linux block stays as upstream wrote it, and the Linux command lines of existing targets must stay byte-identical (compare `make -n -B` before/after). The macOS block uses the `*_mac.*` sources instead of the Linux-only ones and compiles `.mm` with `-fobjc-arc`; it needs GNU make 4 (`gmake`). On macOS the third-party libraries, `zen/`, the engine (`gmake -C FreeFileSync/Source engine`) and both apps build: `gmake -C FreeFileSync/Source` and `gmake -C FreeFileSync/Source/RealTimeSync` link the apps and make `Build/Bin/macos-<arch>/{FreeFileSync,RealTimeSync}.app` side by side with `FreeFileSync/Source/mac_bundle.sh` (Info.plist, icns, Resources, ad-hoc signature; bundle ids `io.github.cuong-tran.*`); GTK code in `wx+/`, `ui/` and the apps is in `ZEN_LINUX` branches with wxOSX code beside it: `FFS_TARGET=macos-arm64|macos-x86_64 .github/build/build.sh` builds the libraries (static, Xcode's clang, deployment target in `common.sh`), `Tests/zen/run.sh` builds and runs the zen tests with Xcode's clang (`ARCH=x86_64` cross-compiles on Apple silicon, run under Rosetta 2); CI: `.github/workflows/macos-build.yml` (libraries, toolchain report, a compile of all of `zen/` against them via `.github/build/macos-report.sh zen-compile`, `libffs_engine.a` for both architectures, a compile of `crash_report_sentry.cpp`, zen tests, both apps per architecture with signature/architecture/minos/`otool -L` checks, the zip artifact `FreeFileSync-<version>-macos-<arch>.zip`, a start check with screenshots (`.github/build/check-mac-app-starts.sh`) and a batch-mode run) and the macOS entries of `zen-tests.yml`, `zip-sync.yml` and `sync-tests.yml`. macOS code in `FreeFileSync/Source` is in `ZEN_MAC` branches in place (`afs/native.cpp`, `afs/zip.cpp`: `st_mtim`; `afs/ftp.cpp`: Latin-1 without glib; `afs/gdrive.cpp`: no `SOCK_CLOEXEC`/`accept4`; `ffs_paths.cpp`, `config.cpp`) or in `*_mac.*` files (`base/icon_loader_mac.cpp`/`.mm`). macOS code in `zen/` is in `ZEN_MAC` branches in place or, for whole features, in `zen/*_mac.cpp`/`zen/*_mac.mm` (Objective-C++ with ARC only there, behind the shared C++ headers): `sys_error_mac.mm` (`formatCFError`, `formatOSStatus`), `dir_watcher_mac.cpp` (FSEvents), `recycler_mac.mm` (`NSFileManager`); `compareNativePath` ignores case and Unicode normalization on macOS, and `legacy_compiler.cpp` has a `strtod_l` fallback for floating-point `from_chars` (Apple's libc++ has it only from macOS 26). Three automated tests: `Tests/sync/run.sh` builds the engine (`make engine`, flags from `make engine-flags`) and runs headless comparisons and synchronizations of temporary folder trees through the real `compare()`/`synchronize()` with a non-interactive `ProcessCallback` (mirror, update, two-way with `.sync.ffs_db`, filters, versioning, recycle bin, symlinks, permissions, errors, ZIP source; macOS: xattrs, FAT image), no wx initialization; needs the FreeFileSync build dependencies and python3; `SYNC_TEST_OBJ` keeps the engine objects; CI: `.github/workflows/sync-tests.yml` (Linux g++, clang + libc++, macOS arm64/x86_64). Two build only what they need (no wxWidgets): `Tests/zip_afs/run.sh` builds the ZIP AFS with its zen dependencies and checks it against generated archives (needs python3 and Info-ZIP `zip`; Linux and macOS; CI: `.github/workflows/zip-sync.yml`), and `Tests/zen/run.sh` runs the unit tests of the `zen/` platform layer (file access, I/O, traversal, paths, `Zstring`, directory watcher, recycle bin, system info, processes, threads, errors, `from_chars` fallback; needs the glib/gio dev packages on Linux, Xcode on macOS; `run.sh <test name>` runs single tests; the scripts honor `CXX`, `STDLIB`, `CXXFLAGS`, `LDFLAGS` and on macOS `ARCH`; CI: `.github/workflows/zen-tests.yml`, Linux g++, clang + libc++ and macOS arm64/x86_64). A test for a feature a porting step has not delivered yet may be a counted `NOT_PORTED_YET_TEST_CASE`, which fails the run unless `ZEN_TEST_ALLOW_NOT_PORTED=1`; none is left. Keep `Tests/zen` and `Tests/sync` test code portable: `std::filesystem` or zen APIs only, with `ZEN_LINUX`/`ZEN_MAC`/`ZEN_WIN` branches (from `zen/build_info.h`) where expected behavior differs. Upstream bugs found by a test are marked `KNOWN_ISSUE`, not fixed in `zen/` or the engine.
- Crash reporting: `zen/crash_report.h` with `crash_report_sentry.cpp` (sentry-native, built by `.github/build/build-sentry-native.sh`) or `crash_report_none.cpp` (default); `make FFS_SENTRY=1` with `SENTRY_DSN` in the environment selects Sentry, and default builds must keep their command lines and contain no sentry code. Report texts go through `zen/crash_scrub.h`; only crashes and `reportInternalError()` are sent, never sync logs or `FileError` texts. `Tests/sentry/run.sh` tests a Sentry build against a fake endpoint; see `CONTRIBUTING.md` (never commit a DSN).
- `Bugs.txt` lists patches upstream applies to its third-party libraries; builds against unpatched libraries may misbehave.
- To see what changed in a release, diff the release commits: `git diff <prev-release-commit> <release-commit> -- FreeFileSync/Source`.
