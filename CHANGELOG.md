# Changelog

Changes made in this repository on top of the official FreeFileSync releases. Upstream's own release notes are in `Changelog.txt` and in the `FreeFileSync <ver>` release commits, and are not repeated here.

Entries are grouped by the upstream release they were made against.

## FreeFileSync 14.13

- Added project docs: `README.md`, `FAQ.md`, `MANUAL.md`, `CONTRIBUTING.md` and `CLAUDE.md`, with images in `docs/images/`.
- Added the `ffs-upstream-update` skill to import new upstream releases into the `upstream` branch and publish GitHub releases.
- Fixed a missing line continuation in `FreeFileSync/Source/Makefile` and `FreeFileSync/Source/RealTimeSync/Makefile` that made GNU make stop with "missing separator" before compiling anything.
- Fixed the malformed `#if  def __GNUC__` conditionals in `zen/argon2.cpp` and `xBRZ/src/xbrz.cpp`, which fail to preprocess as soon as `__GNUC__` expands to a number.
- Changed the multi-arch Linux build workflow to build the checked-in tree: FreeFileSync and RealTimeSync for amd64 and arm64 on native GitHub runners in an Ubuntu 26.04 container, with the `Bugs.txt` library patches applied (wxWidgets 3.3.4 built from source with the `settings.h` color hook and without exception handling, libssh2 built from a pinned `1.11.2_DEV` commit with the `MAX_SFTP_*` constants made public), and with the glib API capped at 2.76 so the `::g_free()` calls compile against glib 2.78 and later. It runs on manual dispatch and on pull requests that change it or the Makefiles, caches the wxWidgets build and uploads the binaries as a tarball artifact instead of publishing prereleases.
- Merged the three Linux build workflows (`linux-multiarch-build.yml`, `build-arm64.yml` and `linux-patched-libs.yml`) into `linux-build.yml`, which builds everything with the `.github/build` scripts. Its packages job builds x86_64 and aarch64 on native Ubuntu 24.04 runners against the patched libraries and uploads a `.deb` and a portable tar.gz per architecture, made by the new `.github/build/package.sh` with OpenSSL, libssh2 and libcurl bundled behind an `$ORIGIN` rpath. A second, compile-only job builds in an Ubuntu 26.04 container against the distribution's OpenSSL and libcurl and an unpatched libssh2 and wxWidgets, so the fallbacks for stock libraries keep compiling. The build scripts gained `FFS_UNPATCHED` (build without the `Bugs.txt` patches) and `FFS_SYSTEM_LIBS` (let `build-free-file-sync.sh` use system libraries), and `.github/scripts/build-wxwidgets.sh` is gone.
- Expanded the Linux build instructions in `CONTRIBUTING.md`: Debian/Ubuntu packages, building libssh2 from a development commit and wxWidgets 3.3 with `--disable-exceptions` from source with the `Bugs.txt` patches, building FreeFileSync and RealTimeSync (with the glib 2.76 API cap needed on glib 2.78 and later), and choosing a compiler through `CXX` in the environment.
- Corrected the build requirements in `CLAUDE.md`: 14.13 builds with `-std=c++26` (GCC 14 or newer), wxWidgets 3.3 and a development libssh2.
- The FreeFileSync and RealTimeSync Makefiles check `wx/settings.h` for the `wxColorHook` patch from `Bugs.txt` and define `ZEN_WX_NO_COLOR_HOOK` only if the check succeeds and finds no hook, so `wx+/darkmode.cpp` declares the hook itself only for a stock wxWidgets (e.g. the 3.3 release tarball or distro packages). A failed check defines nothing, so the compiler reports the real error. Builds against a patched wxWidgets are unchanged; with a stock wxWidgets the makefiles print a warning naming `Bugs.txt` and the higher-contrast gray text in dark mode is lost. `CONTRIBUTING.md` notes that the color hook is the only wxWidgets patch the build needs.
- Updated the `Dockerfile` for 14.13: Ubuntu 26.04 with GCC 15 (C++26), libssh2 from a pinned 1.11.2 development commit (14.13 needs `LIBSSH2_ERROR_STORE_OVERFLOW`), libcurl 8.21.0 and wxWidgets 3.3.4 built with `--disable-exceptions` and the `Bugs.txt` `wx/settings.h` patch (as a unified diff that also includes `<memory>`), with the glib API capped at 2.76 so upstream's `::g_free(...)` calls compile. All three source downloads are checked against pinned SHA-256 values. By default it builds FreeFileSync and RealTimeSync from the mounted source tree.
- `FreeFileSync/Source/Makefile`: the default `make` again writes `FreeFileSync/Build/Bin/` like upstream; `make BUILD=debug` builds into `FreeFileSync/Build/Debug/` with separate objects, replaces its `Resources` copy on every build and keeps `NDEBUG`; an unknown `BUILD` value is an error; objects without a `.d` file (e.g. from an older build) are rebuilt.
- Both makefiles keep object files in `FreeFileSync/Build/Obj/` (and `Build/Debug/Obj/`) inside the checkout instead of a fixed folder in the shared temp directory, so checkouts don't mix objects and other users can't plant files there.
- Added a `.gitignore` for the build output folders.
- `CONTRIBUTING.md`: added a "Build in Docker" section and the debug build; `CLAUDE.md` points to both.
- Updated the dependency build scripts in `.github/build/` for 14.13: they default to the library versions in `Bugs.txt`, add libssh2 (a pinned 1.11.2_DEV snapshot built with CMake), apply every `Bugs.txt` fix from `.github/build/patches/`, build wxWidgets with `--disable-exceptions`, verify download checksums, install into `.build/deps` with an rpath, and build FreeFileSync and RealTimeSync with the upstream makefiles, with the glib API capped at 2.76 for glib 2.78 and later. Usage is in `.github/build/README.md`.
- Turned the dependency CI workflow into `linux-patched-libs.yml`, which builds the patched libraries and both apps on Ubuntu 24.04 with g++ 14, checks that the binaries load the patched libraries, and uploads them with those libraries as a tarball. It runs on pushes to `main`/`dev`, on pull requests that touch the sources or the build scripts, and on demand.
- Adapted the read-only ZIP archive support to 14.13: `#pragma once` header, Makefile entries in the 14.13 syntax, the ZIP test built with `-std=c++26` and the Makefile's warnings in a `gcc:15` container and linked against gio, a SIGPIPE abort in the test fixtures fixed, and the full-build CI job (wxWidgets 3.3.1, too old for 14.13) dropped.
- Hardened the ZIP reader: Zip64 central-directory sizes that would overflow are rejected instead of crashing, a missing archive reads as "does not exist" for inner paths too, all error texts go through `_()`, entry names containing NUL are skipped, a name that is both a file and a folder is kept as the folder only, the index cache also checks nanosecond mtime and inode, archives with more than 65535 entries but a wrapped 16-bit entry count are listed completely, an end-of-central-directory signature inside the archive comment is no longer mistaken for the real record, and archive paths may contain `|`. The comparison warns when a ZIP archive used as a base folder lies inside any base folder, which a mirror sync would otherwise delete.
- Added missing-archive, wrapped-entry-count, `|`-in-name, unsafe-entry-name and fake-EOCD-in-comment cases to the ZIP test.
- Documented the ZIP file system and `Tests/zip_afs/run.sh` in `CLAUDE.md` and `CONTRIBUTING.md`.
- `zen/build_info.h` defines exactly one of `ZEN_LINUX`, `ZEN_MAC` and `ZEN_WIN` from the compiler's predefined macros (`__linux__`, `__APPLE__`, `_WIN32`) and stops with an error on any other platform. Nothing branches on them yet; they are the base for the macOS and Windows ports in `docs/PORTING_PLAN.md`.
- Added the zen unit tests `Tests/zen/run.sh`: about 470 checks over the platform layer in `zen/` (file access, symlinks, permissions, file I/O, traversal with Unicode and long names, path helpers and macro expansion, `Zstring`, directory watcher, recycle bin, system information, processes, threads, error texts), without a test framework, each test in a fresh temporary folder, with the recycle bin sandboxed. Written to run unchanged on macOS and Windows later, branching on the `ZEN_*` macros where behavior differs. Two upstream bugs are recorded as known issues: `formatGlibError()` formats `G_FILE_ERROR` codes as errno values (so a missing file reads "EINTR: Interrupted system call"), and `getUserDownloadsPath()` fails instead of falling back to `~/Downloads` when `xdg-user-dir` is not installed. The new `zen tests` workflow runs them on Ubuntu in a `gcc:15` container.
- Documented `Tests/zen/run.sh` in `CLAUDE.md` and `CONTRIBUTING.md`.

## FreeFileSync 14.11

- Added read-only ZIP archives as a sync source: a `zip:` AbstractFileSystem in `afs/zip.cpp` with its own central-directory parser (Zip64, self-extracting prefix, UTF-8/CP437 and Info-ZIP Unicode names, extended/NTFS timestamps). It inflates through zlib, checks CRC32 and size, and caches the parsed index per archive. Write operations fail with "Operation not supported by device". Syntax: `zip:/path/archive.zip`, or `zip:/path/archive.zip|inner/folder`. Dropping a `.zip` file on a folder field selects the archive. Typical use is "Mirror" from the archive to a folder, which extracts only new and changed files and deletes obsolete ones.
- Added the standalone ZIP test `Tests/zip_afs/run.sh` (archives made by Python zipfile and Info-ZIP: stored, deflate, Zip64, CRC corruption) and a GitHub Actions workflow that runs it.

## FreeFileSync 14.9

- Added a GitHub Actions workflow (`.github/workflows/build-arm64.yml`) that builds FreeFileSync and RealTimeSync for Linux ARM64 on every push and pull request to `main` and `dev`, in an Ubuntu 26.04 container on a native arm64 runner. It builds wxWidgets 3.3.4 with the `wxColorHook` patch from `Bugs.txt` and `--disable-exceptions` (`.github/scripts/build-wxwidgets.sh`, cached) and an unpatched libssh2 from a pinned development commit, and packages the result as a `.deb` that installs `Bin/` (with the bundled libssh2), `Resources/` and launchers under `/opt/FreeFileSync`, plus a portable `tar.gz`.
- `libcurl/curl_wrap.cpp` builds against libcurl older than 8.11.1 (checked down to 8.5): `LIBCURL_VERSION_NUM` checks guard `CURLE_TOO_LARGE` (8.6.0), `CURLE_ECH_REQUIRED` (8.8.0) and `CURLE_OBSOLETE34`/`41` (8.11.1, with the older names used before that).
- `afs/sftp.cpp` falls back to libssh2's value of 30000 for `MAX_SFTP_READ_SIZE` and `MAX_SFTP_OUTGOING_SIZE` when stock libssh2 headers lack them. A libssh2 patched as described in `Bugs.txt` still uses its own definitions.
- Added a `Dockerfile` with a Linux build environment that builds libssh2, libcurl and a static wxWidgets with the `Bugs.txt` `wx/settings.h` patch from source.
- `FreeFileSync/Source/Makefile`: added a debug build mode (`make BUILD=debug` / `make debug`, `-g3 -O0`) and header dependency tracking (`-MMD -MP`).
