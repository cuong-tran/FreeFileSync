# Changelog

Changes made in this repository on top of the official FreeFileSync releases. Upstream's own release notes are in `Changelog.txt` and in the `FreeFileSync <ver>` release commits, and are not repeated here.

Entries are grouped by the upstream release they were made against.

## FreeFileSync 14.13

- Added project docs: `README.md`, `FAQ.md`, `MANUAL.md`, `CONTRIBUTING.md` and `CLAUDE.md`, with images in `docs/images/`.
- Added the `ffs-upstream-update` skill to import new upstream releases into the `upstream` branch and publish GitHub releases.
- Fixed a missing line continuation in `FreeFileSync/Source/Makefile` and `FreeFileSync/Source/RealTimeSync/Makefile` that made GNU make stop with "missing separator" before compiling anything.
- Fixed the malformed `#if  def __GNUC__` conditionals in `zen/argon2.cpp` and `xBRZ/src/xbrz.cpp`, which fail to preprocess as soon as `__GNUC__` expands to a number.
- Changed the multi-arch Linux build workflow to build the checked-in tree: FreeFileSync and RealTimeSync for amd64 and arm64 on native GitHub runners in an Ubuntu 26.04 container, with the `Bugs.txt` library patches applied (wxWidgets 3.3.4 built from source with the `settings.h` color hook and without exception handling, libssh2 built from a pinned `1.11.2_DEV` commit with the `MAX_SFTP_*` constants made public), and with the glib API capped at 2.76 so the `::g_free()` calls compile against glib 2.78 and later. It runs on manual dispatch and on pull requests that change it or the Makefiles, caches the wxWidgets build and uploads the binaries as a tarball artifact instead of publishing prereleases.
- Merged the three Linux build workflows (`linux-multiarch-build.yml`, `build-arm64.yml` and `linux-patched-libs.yml`) into `linux-build.yml`, which builds everything with the `.github/build` scripts. Its packages job builds x86_64 and aarch64 on native Ubuntu 24.04 runners against the patched libraries and uploads a `.deb` and a portable tar.gz per architecture, made by the new `.github/build/package.sh` with OpenSSL, libssh2 and libcurl bundled behind an `$ORIGIN` rpath. A second, compile-only job builds in an Ubuntu 26.04 container against the distribution's OpenSSL and libcurl and an unpatched libssh2 and wxWidgets, so the fallbacks for stock libraries keep compiling. The build scripts gained `FFS_UNPATCHED` (build without the `Bugs.txt` patches) and `FFS_SYSTEM_LIBS` (let `build-free-file-sync.sh` use system libraries), and `.github/scripts/build-wxwidgets.sh` is gone.

- Corrected the build requirements in `CLAUDE.md`: 14.13 builds with `-std=c++26` (GCC 14 or newer), wxWidgets 3.3 and a development libssh2.
- The FreeFileSync and RealTimeSync Makefiles check `wx/settings.h` for the `wxColorHook` patch from `Bugs.txt` and define `ZEN_WX_NO_COLOR_HOOK` only if the check succeeds and finds no hook, so `wx+/darkmode.cpp` declares the hook itself only for a stock wxWidgets (e.g. the 3.3 release tarball or distro packages). Builds against a patched wxWidgets are unchanged; with a stock wxWidgets the makefiles print a warning naming `Bugs.txt` and the higher-contrast gray text in dark mode is lost. `CONTRIBUTING.md` notes that the color hook is the only wxWidgets patch the build needs.

- macOS: on FAT, exFAT and other volumes without native extended attributes, the native traversal no longer reports an AppleDouble companion `._X` when `X` exists in the same folder. macOS 13+ tags every item a provenance-tracked process creates (a downloaded app the user opened, or Homebrew's programs) with `com.apple.provenance`, which such a volume keeps as `._X` and the process can't remove; on macOS 27.2 every file and folder a mirror created there came back as a target-only `._` item. ## FreeFileSync 14.11

- Added read-only ZIP archives as a sync source: a `zip:` AbstractFileSystem in `afs/zip.cpp` with its own central-directory parser (Zip64, self-extracting prefix, UTF-8/CP437 and Info-ZIP Unicode names, extended/NTFS timestamps). It inflates through zlib, checks CRC32 and size, and caches the parsed index per archive. Write operations fail with "Operation not supported by device". Syntax: `zip:/path/archive.zip`, or `zip:/path/archive.zip|inner/folder`. Dropping a `.zip` file on a folder field selects the archive. Typical use is "Mirror" from the archive to a folder, which extracts only new and changed files and deletes obsolete ones.
- Added the standalone ZIP test `Tests/zip_afs/run.sh` (archives made by Python zipfile and Info-ZIP: stored, deflate, Zip64, CRC corruption) and a GitHub Actions workflow that runs it.

## FreeFileSync 13.7

- Added scripts in `.github/build/` that build OpenSSL, libcurl and wxWidgets from source into the repository, and a GitHub Actions workflow that runs them.
